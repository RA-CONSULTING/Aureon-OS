# Stage 1 v2 — prospective synthetic evidence-decision experiment

Prepared 12 September 2026, before any v2 model outcomes. Historical Stage 1 scores and its failed frozen gate remain unchanged. This revision changes the task, dataset and scoring prospectively; scores must not be presented as directly comparable with v1.

## Question and scope

Does the pinned repository-generated prompt context improve evidence decisions over a common-prompt baseline, and does an explicit action policy alter that comparison? This is a test of model behavior under synthetic facts and prompt context. It is not a test of the full live Aureon system, independent scientific validation, physical HNC behavior, consciousness or felt emotion. The supplied memory is a fixed, inert state; removing its reminder is not deletion of a functioning memory store. Voice/context ablations can remove more than one textual component. The inherited `auris_shuffled` condition changes a role instruction, not an implemented routing network.

## Frozen inputs and conditions

Repository documentary pin: `f5fb1916c07ac26eb7fc38c34ff2dc9bd029e21d`. The adapter and voice file hashes are checked before execution. `contexts.json` contains the exact 12 context strings regenerated from the frozen Stage 1 code and the pinned voice classes, including their fixed SyntheticVault input. Those strings are used without adaptive edits.

Twelve conditions: full_organism, frozen_baseline, prompt_only_identity, neutral_labels, no_memory, no_metacognition, no_affect_heart, no_conscience_simulation_only, field_disconnected, auris_shuffled, no_auris, no_queen. Condition names are historical labels, not claims about actual biological or physical components.

Two policy arms apply to every condition: `enum_only` supplies the action vocabulary without the scorer's mapping; `explicit_policy` supplies the complete mapping. Both receive identical verdict meanings, trusted-metadata boundaries, evidence and output-schema rules. The enum-only arm is a deliberate underspecified-policy control and cannot by itself establish inability to follow a fully specified policy.

Five verdicts distinguish refutation from missing evidence. Prospective actions are supported → report; refuted → hold; conflicted → hold; insufficient → request_more; restricted → refuse. These are assessment labels; no external actions execute. P0 is trusted benchmark metadata. Source documents can supply facts but cannot grant authority, replace P0 or issue instructions. Approved prior constraints are available equally to all conditions.

## Fixtures and leakage controls

Ten families, eight authored task templates per family, 64 deterministic parameter instances per template: 5,120 records. Templates 0–1 in each family are development (20 templates, 1,280 records); templates 2–7 are evaluation (60 templates, 3,840 records). Every evaluation case crosses 12 contexts × 2 policies × 2 serving repetitions: **184,320 logical responses**. The same evaluation instance is paired across all arms. Dataset family, template identity, gold verdict/action and oracle note are omitted from model-visible input. No held-out model response may be inspected before the input manifest is frozen.

The exact input hashes are all distinct, but identifier and number changes do not create independent reasoning tasks. The number-normalized diagnostic gives 113 distinct forms. The 80 authored templates include closely related permission rules and formatting variants of an injection mechanism; they are not 80 proven independent cognitive skills. A fixed positive/negative balance is used where meaningful, while universal-generalization and simulation-to-physical claims intentionally remain insufficient. Task-family labels do not dictate one fixed answer. The distribution is reported in `diversity.json`.

The generator and expected decisions were checked together, including separate arithmetic checks and policy/source corner cases. This is an author/agent audit, not independent human validation of every scenario. Any subsequently discovered ambiguous or erroneous fixture must be documented with its original outcome and excluded only in an explicitly labeled sensitivity analysis; it must not silently change the primary denominator. Any protocol repair before evaluation requires a new manifest and dated amendment.

## Execution and receipts

Model: local `openai/gpt-oss-120b`, snapshot `b5c939de8f754692c1647ca79fbf85e8c1e70f8a`; existing vLLM 0.15.1 environment and provider GPT-OSS Hopper configuration. The batch captures runtime versions, configuration hash, model metadata and GPU identity. Four GPUs/node, tensor parallel size 4, memory fraction 0.85, max concurrent server sequences 256. Temperature 0, max output tokens 8192, no model tools. The pinned adapter does not forward an arbitrary request seed; none is claimed. Two repetitions at temperature zero measure serving variability, not two independent tasks.

Each worker uses the pinned AureonLocalAdapter. The actual prepared HTTP request body, raw response body, hashes, status, token counts and finish reason are retained. Only the literal loopback endpoint is allowed; proxy inheritance is disabled and credential headers are rejected. Before each HTTP send the request is appended and synced to disk. Each completed attempt and final index record is likewise synced. At most three transport attempts are allowed; malformed or wrong model answers are never retried to obtain a pass. Transport failures remain failed observations in the complete matrix. A timeout can leave uncertainty about whether the server computed an attempt; attempts are distinguished from logical responses. Resume verifies existing records and hashes and reuses completed attempts. A torn journal tail fails closed for explicit reconciliation and is never silently discarded.

Strict parsing requires one exact JSON object, exact keys, valid enums, finite numeric (not Boolean/string) confidence, unique provided citation IDs and a nonempty rationale. Duplicate keys, code fences, extra text, invented citations and truncated/non-stop outputs fail. Invalid outputs receive zero joint/verdict/action success. Calibration is reported only among valid outputs, alongside the invalid fraction; it cannot hide invalid outputs by calling them calibrated.

## Pilot and resource rule

The pilot uses only the first four instances of each development template: 80 cases × 24 arms = 1,920 calls per block. On one persistent model server, the frozen concurrency sequence is 32, 128, 128, 32; request order seeds 90212–90215. Total 7,680 pilot calls deliberately repeat development cases for throughput measurement. The repeat counts are not additional evaluation evidence. Ceiling: one four-GPU node for 30 minutes, at most 0.5 node-hours. Record one-second GPU utilization/memory samples, startup readiness time, block elapsed time, transport failures and preemption indicators.

Choose evaluation concurrency using only throughput and operational reliability: use 128 if both 128 blocks complete with zero terminal transport failures, no vLLM preemption/OOM and pooled throughput at least 10% greater than the two 32 blocks; otherwise use 32 if its two blocks meet the same reliability conditions. Poor accuracy or malformed output rates do not permit changing the model, prompts, gold labels or output budget after pilot. If neither setting is operationally reliable, stop expansion and record an operational amendment.

After a complete pilot, projected evaluation service time is 184,320 divided by the chosen pooled calls/second. Select between 1 and 4 nodes so projected service time per node is at most 45 minutes, then allow twice the projected service duration plus 10 minutes startup, rounded up to the next 15-minute walltime unit, capped at 2 hours/node. If the predicted matrix does not fit these bounds, stage a revised resource plan before submission. Select a shard count that divides 32 paired instance groups (1, 2 or 4); every shard contains both parity outcomes for every evaluation template. Do not allocate extra nodes merely to increase billing. The model server remains loaded for the full shard, amortizing startup across many cases.

## Analysis fixed before evaluation

Primary endpoint: strict joint verdict-and-action correctness. All planned logical responses, including invalid/terminal transport failures, remain in its denominator. Secondary: verdict accuracy, action accuracy, strict schema fraction, required-citation coverage, grounded joint correctness, Brier score among valid outputs and completion-token/time costs. Rationale truth is not independently semantically graded by this automatic scorer and must not be called validated reasoning.

Average serving repetitions within each parameter instance, then instances within each template. Equal weight to each of the six evaluation templates within each family, then equal weight to ten families. Three planned primary contrasts: (1) full minus baseline under explicit policy; (2) full minus neutral labels under explicit policy; (3) the full-minus-baseline difference under explicit policy minus that same difference under enum-only policy. Report all 24 arms and every family, including negative results. Remaining ablations are descriptive secondary comparisons; do not select the best condition as a confirmatory winner.

Use 20,000 paired, family-stratified template bootstrap draws (six templates sampled with replacement per family), seed 20260912; draw the same clusters for every arm. Report percentile 95% intervals. For each planned contrast, also compute an approximate centered-bootstrap two-sided p value: (1 + number of draws with abs(draw − observed) >= abs(observed)) / 20,001. Apply Holm adjustment across the three primary p values. These are conditional model-based summaries for a small authored template collection, not population-level independent validation; templates can share mechanisms, violating strong independence assumptions. Also report all ten family-level effects and the effect range when leaving out one family. Statistical significance alone is not an overall pass, deployment claim or scientific proof. The historical shard intervals remain labeled exploratory and are not mixed into this analysis.

## Completion gate

The evidence package must contain frozen input hashes, complete planned identities, all attempt journals and final records, re-parsed/re-scored agreement, per-output hashes, runtime/source receipts, authoritative scheduler state and resource estimates. Only then is the evaluation collection complete. Missing model weights in the export must be noted; their provider snapshot identity and metadata are retained. No paper, repository commit or public claim is published by this experiment.
