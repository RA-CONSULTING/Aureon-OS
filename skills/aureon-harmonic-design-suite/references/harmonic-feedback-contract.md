# Design Nexus feedback contract

## Purpose

The Design Nexus adapts a Harmonic Nexus weighted-feedback pattern into an operational design-control loop. It does not prove scientific theory, commercial outcomes, or visual taste.

The loop is:

`sense -> orient -> branch -> compose -> prove -> challenge -> retain/revert -> package -> release -> learn`

Before a successor candidate is scoped, `sense` includes a read-only comparison
of selected public HTTPS routes with the local canonical presentation. A drift
receipt is evidence, not an automatic source-selection action: preserve both
records, acquire a fresh verified backup, and require an explicit owner-scoped
reconciliation before treating either surface as the new baseline.

## Score

Compute a bounded operational score:

`100 * clamp(0.30S + 0.25C + 0.20R + 0.15F + 0.10X)`

- `S`, source strength: current claim inputs and fresh official competitor evidence.
- `C`, coherence: proposition, route IA, metadata, design tokens, components, and copy alignment.
- `R`, repeatability: the same result across routes, viewports, browsers, keyboard paths, and repeated runs.
- `F`, feasibility: accessibility, performance, asset budgets, implementation safety, and maintainability.
- `X`, contradiction control: unsupported-claim, regression, conflict, and veto handling.

Record the dimension values, weights, score, minimum, phase spread, source hash, and test-policy hash. Do not change thresholds during the same improvement run.

## Objective design council

Any critical veto blocks acceptance:

- strategy and brand;
- evidence and claim discipline;
- information architecture, grammar, and journey copy;
- accessibility;
- responsive layout;
- motion and reduced-motion behaviour;
- performance and resource loading;
- browser/runtime behaviour;
- package, release, and security.

Human visual acceptance remains required for material brand changes. Automated screenshot difference detects change, not beauty.

## Deterministic gates

- Toolchain: record Python, Node, browser, OS, and test-script hashes.
- Source: bind source tree, config, brief, evidence snapshot, and benchmark snapshot.
- Live-surface reconciliation: record selected local-route hashes and public HTTPS presentation fingerprints before a successor candidate is scoped. The bounded fingerprint covers title, description, canonical, normalised visible text and key interaction/accessibility surface (CTA/form targets and image labels), not pixel-level visual equivalence. `aligned` remains observational; `drift-detected` or `incomplete` blocks baseline assumptions until an owner-scoped reconciliation is bound to a fresh verified backup. Never use it to copy public content, promote a candidate, package or deploy.
- Website-source rationalisation: after live reconciliation has selected the canonical `website/` tree, `aureon.operator.website_source_rationalisation` may create an optional read-only plan only through the externally hash-checked isolated launcher. It binds the unchanged source manifest to the authenticated reviewed release builder's bounded `-VerifyOnly` closure and partitions every file into retained or `not-in-public-runtime-closure`. Project the retained tree against fixed maxima of 4,500,000 total bytes, 2,200,000 image bytes, 350,000 CSS bytes, and a 500,000-byte largest non-code asset, but keep the result `blocked-candidate-qa-not-run` and ineligible for the next local gate. The module may validate only one separately supplied exact named-owner review acknowledgement whose window is at most four hours; the path-owned writer generates and deterministically replays the receipt itself, the decision and validation both carry `staging_authority: none`, and the module cannot create the decision or stage anything. Omission does not prove safe deletion or source/candidate readiness, and neither plan nor validation grants source mutation/removal, staging, candidate, package, release, credential, network, publishing, or deployment authority.
- Candidate: autonomous V30+ work begins from a reconciled v4 exact-path order and a complete source-tree baseline. The order binds a current public-surface observation; when local and production records drift, it also binds a fresh verified backup and an explicit time-limited owner decision to retain local source for staged work. Rights readiness remains provenance-only: `candidate_use_rights_ready` means that an exact named-human per-asset rights capsule is current, while every global registry view keeps `candidate_asset_ready: false`. Only a candidate-specific runner state bound to an immutable importer receipt and current replay may say `candidate-assets-ready`.
- Asset-bearing candidate sequence: the runner stages the pristine candidate as `candidate-staged`; trusted orchestration imports the complete work-order-declared WebP batch; the runner persists and replays the fixed candidate-local receipt; and only then does it record `candidate-assets-ready` and permit a text-worker context or broker lease. The worker has no binary read, write, copy, or import authority and cannot invoke the importer or assert the asset-ready state. Text-only candidates skip the importer, remain `candidate-staged` until validation, and never enter `candidate-assets-ready`.
- Candidate structural surface replay: after controlled text edits, final validation recomputes the public structure and asset references from the current staged bytes. Separately controlled text deltas may remain, but the binary projection must equal the source-bound baseline plus the exact importer receipt. Missing, undeclared, unbound, remote, embedded-media, or otherwise binary-smuggled asset references are vetoes; worker-supplied “assets ready” text is never evidence.
- Candidate worker: one short-lived broker lease seals the exact route, claim capsule, design directives and complete candidate-tree snapshot. Version 1 applies submitted data through a built-in declarative manifest applier only; it does not run arbitrary worker code. Every declared test must be passed, and the broker rejects symbolic/reparse and hard-linked candidate paths before proving the post-work text delta matches the manifest exactly, consuming the lease and retaining immutable failure evidence. Before candidate validation, the broker also requires a `claim_surface_manifest` (an empty list is explicit for no-copy work). The claim-surface control compares new static public text against the canonical baseline and accepts it only when every new surface is hash-bound as exact permitted route wording, its exact boundary, or a non-claim without a prohibited inference. The worker never receives a repository root, generic shell, network, credential, package, promotion or deployment capability.
- Candidate authority: provenance rights readiness, the importer receipt, `candidate-assets-ready`, structural surface replay, worker delivery and candidate validation are local evidence with no release authority. They cannot mutate canonical `website/`, promote, package, access credentials, release, publish or deploy.
- HTML/IA: valid routes, unique IDs/titles/canonicals, no orphan or broken local references.
- Claims: every material claim maps to source, state, checked date, expiry, boundary, and permitted wording.
- Copy: pinned en-GB spelling/style, terminology glossary, and CTA/journey lint.
- Investor-copy quality: carry the current bounded audit as the exact `investor_copy_quality_current` hard gate. Retain only its privacy-minimised policy, route, finding-hash and aggregate-count binding; never copy raw public wording or findings into worker context. The copy audit has no release authority, and WebsiteOperator must rerun the exact binding before release packaging.
- Accessibility: WCAG 2.2 AA objective checks, focus, keyboard, reflow, zoom, and target size.
- Responsive: 360, 390, 768, 1280, 1440, and 1920 widths with no clipping or unintended overflow.
- Visual regression: frozen clock, network, fonts, and animation; approved baseline manifest.
- Interaction/motion: pointer, keyboard, history, resize, and reduced-motion parity.
- Performance: pinned budgets and repeated measurements; zero failed required resources.
- Security/privacy: no secrets, mixed content, unexpected trackers, or private operator routes.
- Benchmark and research refresh: official sources within freshness policy and redacted local public-source snapshots; missing evidence stays missing. A `not-cleared` artwork policy blocks new artwork use rather than being converted into a permissive assumption.
- Package: manifest equals transitive runtime dependency closure and extracted package works offline.
- Candidate provenance: block undeclared path changes, file removal, secret-like content, blocked files, undeclared remote origins, stale baselines, receipt-layout substitution, a changed material source without a semantically current staged claim register, unclassified newly rendered public text, or any static text surface that is outside its sealed route claim capsule.
- Candidate visual review: bind the staged candidate-control tree and independent QA-format source inventory to full browser evidence, screenshot hashes, completed named pixel dispositions, and a separate named human acceptance receipt. It remains local evidence only; canonical V28 release evidence is rerun after promotion.
- Deployment: fresh backup, exact package-hash owner approval, explicit upload, live route and resource read-back.

## Learning

Promote an accepted repair or pattern as a versioned skill only when it carries:

- input and output contract;
- allowed paths and authority;
- source and policy hashes;
- passing tests;
- example evidence;
- refresh deadline;
- execution and regression history.

Record that evidence first through `aureon.operator.design_learning_ledger`.
Its append-only record is a source-bound, human-reviewed proposal for a future
skill edit; it does not write the skill, the canonical website, a package or a
deployment state. The proposal must bind exact candidate paths, current staged
visual evidence, existing regression tests and a bounded refresh deadline.

Rejected candidates remain in append-only evidence; do not erase failed iterations.
